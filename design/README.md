## What we took from Detroit: Become Human

Kept, but toned down so pages stay fast and readable:

| In the game | On the site |
| --- | --- |
| Bright, sterile white-blue world, muted slate-blue UI | Light theme by default (`#EEF2F5` ground, `#2A5680` accent, between the game's slate `#3F5670` and a brighter blue). Dark theme via the toggle |
| Blurred bright room behind the menus (the Chloe screens) | `public/bg/room-*.webp`: soft pools of light only (window streaks removed as distracting), generated by `make-background.mjs`, loaded after the page, slow drift + scroll parallax. Overshoots the screen by 25% top and bottom (`150lvh`) so mobile toolbars never uncover or resize it |
| Large translucent triangles | One SVG of soft facets over the room, low contrast, drifting and parallaxing at a different speed for depth |
| Corner-bracket selection frame (`⌜ ⌟`) | Hover/focus state of cards, buttons, sub-page links, previous/next; always on callouts (one corner) |
| Selected bar with a sharp shadow falling straight down | Only the Resume button: muted navy gradient, no border; a short shadow band above and a longer one falling straight down, exactly button-width, slowly breathing; a sheen every few seconds. Everything else uses the outlined button |
| Menu text with a faint offset ghost copy ("ENG", "JPN") | Page titles and the home name keep a faint offset echo; on load they're revealed left to right while the echo slides in from wide and settles |
| Uppercase tracked labels, mixed weights ("AKIF **KAZI**"); no logo, the lettermark "AKIF KAZI" / "AK" is the mark | Montserrat (closest free match to the game's Gotham-like UI face) for display text only; body stays system UI |
| Loading screen: bar + "34%" bottom-left | Reading progress at the bottom of the left rail on desktop (a thin top bar on smaller screens) |
| Settings list: label left, value right, hairlines | Facts strip on home, project meta, `Key:: value` fact lists |

Left out on purpose: cut/sliced imagery, glitch effects, content fading in on scroll, hover effects on things that aren't clickable (images), decorative text that says nothing (numbering, counts, "end of file").

## Layout

- Home: no top bar, only the theme switch; the name, projects and notes are the navigation.
- Desktop (≥1200px) articles: sticky left rail (lettermark home link, chapters, progress) and right rail (site nav, theme, this page's role/year/tags, previous/next). The top bar and bottom pager hide there.
- Smaller screens: top bar, thin progress bar, previous/next at the end of the page.

## Rules

- Sharp corners everywhere. No `border-radius`.
- Icons: [Material Symbols Sharp](https://fonts.google.com/icons), weight 200, from `build/icons/` (see `build/icons.mjs` to add one). One set only. Arrows must point the way the link goes.
- Hover effects only under `@media (hover:hover) and (pointer:fine)`, and only on things you can click; touch gets `:active` feedback instead.
- Motion only under `prefers-reduced-motion: no-preference`. The background image is skipped on data-saver.
- Transparent images (drawn for Notion's dark theme) get a dark backdrop (`--media`, `#141B23`) baked into the image files at build time, so they also read right in reader mode and link previews.
- No text that repeats what's already on screen.
